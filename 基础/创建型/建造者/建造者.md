# 建造者

## Builder（生成器）

# 建造者模式（Builder）深度透析

建造者解决的核心问题是：**如何分步骤、可控地构建复杂对象**，把「构建过程」与「最终产品」分离，避免构造函数参数爆炸。

------

## 1. 意图与本质

GoF 定义：将一个复杂对象的构建与其表示分离，使得同样的构建过程可以创建不同的表示。

用一句话说：

> **分步构建 + 隐藏细节 + 最终一次性产出**

### 核心作用（简要）

1. **分步设置**：链式调用，可读性高，不必一次性传 20 个参数。
2. **隐藏构建细节**：客户端不需要知道对象内部如何组装。
3. **同一流程，不同结果**：同一 Builder 流程可产出不同配置的对象。
4. **可选步骤**：某些步骤可跳过（如无 Buff 的角色）。

------

## 2. 结构拆解

```
┌──────────┐     分步调用      ┌─────────────┐     Build()     ┌─────────┐
│  Client  │ ───────────────► │   Builder   │ ──────────────► │ Product │
└──────────┘                   └─────────────┘                 └─────────┘
                                     │
                               持有/组装 Product
                               的中间状态
```

| 角色 | 职责 |
| :--- | :--- |
| Builder（建造者） | 定义分步构建接口，持有中间状态 |
| ConcreteBuilder（具体建造者） | 实现各构建步骤，定义 Build 产出最终对象 |
| Product（产品） | 被构建的复杂对象 |
| Director（指挥者，可选） | 按固定顺序调用 Builder 步骤 |

> Director 是可选的。很多项目（尤其游戏）由客户端直接链式调用 Builder，不必单独写 Director。

------

## 3. 关键机制：流畅接口（Fluent Interface）

建造者最常见的用法是**链式调用**：

```cpp
Character Hero = CharacterBuilder{}
    .SetName("Aura")
    .SetClass(EClass::Mage)
    .SetLevel(10)
    .AddSkill("Fireball")
    .AddSkill("IceShield")
    .Build();
```

每一步返回 `*this`（或 `Builder&`），让构建过程像 DSL 一样可读。

### 与构造函数对比

```cpp
// ❌ 参数过多，可读性差，可选参数难处理
Character("Aura", EClass::Mage, 10, {}, {}, true, false, 100, 50);

// ✅ 建造者：语义清晰，步骤可选
CharacterBuilder{}.SetName("Aura").SetClass(EClass::Mage).SetLevel(10).Build();
```

## 4. C++ 示例骨架

### 4.1 基础建造者

```cpp
class Character {
public:
    std::string Name;
    int Level = 1;
    std::vector<std::string> Skills;
};

class CharacterBuilder {
    Character Product;

public:
    CharacterBuilder& SetName(const std::string& Name) {
        Product.Name = Name;
        return *this;
    }

    CharacterBuilder& SetLevel(int Level) {
        Product.Level = Level;
        return *this;
    }

    CharacterBuilder& AddSkill(const std::string& Skill) {
        Product.Skills.push_back(Skill);
        return *this;
    }

    Character Build() {
        return std::move(Product);
    }
};

// 使用
Character Hero = CharacterBuilder{}
    .SetName("Hero")
    .SetLevel(5)
    .AddSkill("Slash")
    .Build();
```

### 4.2 强制通过 Builder 创建（隐藏 Product 构造函数）

```cpp
class Character {
    friend class CharacterBuilder;
    Character() = default;  // 私有构造，外部不能直接 new

public:
    std::string Name;
    int Level = 1;
};

class CharacterBuilder {
    Character Product;
public:
    CharacterBuilder& SetName(const std::string& Name) {
        Product.Name = Name;
        return *this;
    }
    Character Build() { return std::move(Product); }

    // 静态入口
    static CharacterBuilder Create() { return CharacterBuilder{}; }
};

// 使用
auto Hero = CharacterBuilder::Create().SetName("Hero").Build();
```

### 4.3 复合建造者（多子 Builder）

当 Product 很大（地址 + 职业 + 装备），可拆成多个子 Builder，仍操作同一个 Product：

```cpp
Person = PersonBuilder::Create()
    .Lives()
        .At("123 London Road")
        .In("London")
    .Works()
        .At("GameStudio")
        .As("Developer")
    .Build();
```

`Lives()` 返回地址 Builder，`Works()` 返回职业 Builder，底层共享同一个 Person 引用。

## 5. 游戏开发中的典型应用场景

### ① 角色 / 敌人初始化

从 DataTable、JSON、存档分步加载：基础属性 → 技能 → 装备 → AI 配置。

```cpp
Enemy = EnemyBuilder{}
    .LoadConfig("Goblin.json")
    .InitAttributes()
    .InitAbilities()
    .InitLootTable()
    .Build();
```

### ② 关卡 / 场景构建

```cpp
Level = LevelBuilder{}
    .SetMap("Forest")
    .AddSpawnPoint(...)
    .AddTriggerVolume(...)
    .SetLighting(...)
    .Build();
```

### ③ 技能 / Buff 组合

分步添加 Effect、Cooldown、Cost、Tag，最后 Build 成 GameplayAbilitySpec。

### ④ UI 动态组装

运行时按配置生成复杂 Widget 树，比 Blueprint 里硬连更灵活。

### ⑤ 网络消息 / 命令对象

分步填充 Header、Payload、Checksum，最后 Build 成可发送的数据包。

## 6. 与相关模式的边界

| 对比 | 建造者 | 区别 |
| :--- | :--- | :--- |
| **抽象工厂** | 创建**一族**配套产品 | 建造者构建**一个**复杂对象，强调**步骤** |
| **工厂方法** | 一个方法创建一个产品 | 建造者用**多个方法**分步组装 |
| **原型** | 克隆已有对象 | 建造者从空/半成品**逐步搭建** |
| **组合模式** | 组织树形结构 | 建造者负责**创建过程**，可产出 Composite 树 |

### 建造者 vs 抽象工厂（最常混淆）

```
抽象工厂：
  Factory.CreateButton() + CreatePanel()
  → 一次得到多个**平级**的配套对象

建造者：
  Builder.SetA().SetB().SetC().Build()
  → 分步组装**一个**复杂对象
```

**记忆口诀**：
- 抽象工厂：**成套生产**（多个产品）
- 建造者：**分步组装**（一个产品）

------

## 7. 优点与代价

### 优点

1. 构建过程清晰，代码可读性高
2. 可以精细控制构建顺序和可选步骤
3. 同一 Builder 可复用于不同配置
4. 符合单一职责：Product 管数据，Builder 管组装

### 代价

1. 简单对象用 Builder 是过度设计（几个参数的构造函数即可）
2. 需要额外维护 Builder 类
3. Build 后若继续修改 Builder，需明确是否允许复用（通常 Build 后应重置或禁止再用）
4. 复合 Builder 类层次可能变复杂

## 8. 在 Unreal Engine 中的对应思想

| 场景 | 近似实现 |
| :--- | :--- |
| Actor 构造 | `ConstructorHelpers`、`CreateDefaultSubobject` 分步添加组件 |
| 蓝图 | 在 Construction Script 里分步设置 |
| GAS | `FGameplayEffectSpec` 链式设置 SetByCaller、Duration 等 |
| 初始化 | `InitPlayerState` → `InitAbilityActorInfo` → `GiveAbilities` 分阶段初始化 |
| DataAsset | 配置 + 运行时 Builder 组装最终对象 |

UE 的 `FBuilder` 风格 API（如 `FGameplayEffectSpecHandle` 的各种 Set 方法）本质就是 Fluent Builder。

## 9. 设计时该怎么用（实战 checklist）

1. 构造函数参数是否 ≥ 4～5 个，或大量可选参数？（是 → 考虑 Builder）
2. 构建是否有**明确步骤顺序**？（加载配置 → 初始化 → 验证 → 产出）
3. 是否需要**不同配置**走同一构建流程？
4. 构建过程是否需要**中间状态**（未完成的 Product）？
5. 对象是否**简单值类型**？（是 → 不必用 Builder）

### 何时不需要 Builder

```cpp
// 简单对象：直接构造或依赖注入即可
FVector Location(0, 0, 100);
FDamageEvent DamageEvent(Damage, HitInfo);
```

------

## 10. 常见反模式

| 反模式 | 问题 | 更好做法 |
| :--- | :--- | :--- |
| 简单对象也写 Builder | 样板代码多 | 用构造函数 |
| Build() 返回指针且 Builder 仍被修改 | 产出对象被意外篡改 | Build 后 move 并重置 |
| 所有逻辑堆在 Build() 里 | 失去分步意义 | 每步职责单一 |
| Builder 与 Product 职责重叠 | 重复代码 | Product 只存数据，Builder 只负责组装 |
| 无验证直接 Build | 产出不完整对象 | Build 前 Validate() |

------

## 11. 小结

建造者不是「另一个构造函数」，而是：

1. 把**复杂构建过程**拆成多个语义清晰的步骤
2. 用**流畅接口**提高可读性
3. 在 `Build()` 时**一次性产出**最终 Product

一句话：**当对象「怎么造」和「造出来是什么」同样复杂时，用建造者。**

------

# 建造者模式的作用（简要）

建造者用来**分步骤构建复杂对象**，避免臃肿的构造函数，让构建过程清晰、可读、可扩展。

## 核心作用

1. **分步构建**：`.SetA().SetB().SetC().Build()`，见名知意
2. **隐藏细节**：客户端不必知道内部如何组装
3. **灵活配置**：可选步骤、不同配置走同一流程
4. **职责分离**：Product 管「是什么」，Builder 管「怎么造」

## 一句话

> **把复杂对象的创建拆成一步步来，最后统一 Build 产出。**

## 游戏里的典型例子

- 角色：`LoadConfig → InitSkill → InitInventory → Build`
- 关卡：分步添加 Spawn、Trigger、Lighting
- GAS：`FGameplayEffectSpec` 链式设置后 Build
- 网络包：分步填充字段后序列化

## 与抽象工厂的快速区分

| | 抽象工厂 | 建造者 |
| :--- | :--- | :--- |
| 产出 | 一族多个对象 | 一个复杂对象 |
| 关注点 | 配套、风格一致 | 构建步骤、可读性 |
| 典型调用 | `CreateA()` + `CreateB()` | `SetA().SetB().Build()` |
